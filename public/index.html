Manual bootstrap validation

                

                  These separate manual controls only run an owner-selected
                  candidate health validation in a disposable, network-denied
                  facet. They grant no inference, external access or automatic
                  promotion. Hosting costs are not metered here.
                

                

                
                

                  Stop persists across restarts and cancels bootstrap
                  validation. It does not stop chat, summaries, Discord or
                  manual tools.
                

                

                  Configure a bounded validation
                  
                  
                  
                  
                  

                    Fixed sandbox: disposable-candidate-v1. Zero paid inference;
                    no external access. Configuration expires after one hour.
                    Failed and interrupted attempts count.
                  

                  
                  
                  
                

                
                

              

              

                
Bounded experiment sessions

                

                  Disabled by default. Configure and explicitly start a
                  subscription-only experiment to generate candidate proposals
                  and run bounded disposable validation. Nothing is activated
                  automatically. No external access or paid inference is
                  allowed; hosting costs are not metered here.
                

                

                
                

                  Stop cancels this experiment’s inference and candidate work.
                  Already-dispatched provider work may finish and consume
                  subscription allowance. Reservations are not refunded. Chat,
                  summaries, Discord and manual bootstrap work are unaffected.
                

                

                  Configure a bounded experiment
                  
                  
                  

                    Uses the exact staged revision ID entered in the manual
                    bootstrap field above and the current saved subscription
                    model. Hard limits: 6 generation dispatches, 1 proposal, 1
                    test; expires one hour after configuration. Requested
                    output-token allowance: 24,576, reserved for planning only.
                    ChatGPT does not enforce this provider output cap; actual
                    output may exceed it. Reported usage is recorded and further
                    work stops when over the allowance. Failed and interrupted
                    reservations count. Sandbox: disposable-candidate-v1.
                  

                  
                  
                

                

                  Saved experiment policy and reservations
                  

                    Output-token reservations are a requested planning
                    allowance, not an enforced provider cap. Actual reported
                    output can exceed that allowance.
                  

                  

                

                
                

                  The report is restricted experiment evidence, not the full
                  conversation or proof of improved behavior. Review candidates
                  separately before any owner activation.
